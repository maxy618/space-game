# Project State And Documentation

1. Read project state/index before starting; verify active task.
2. Update status only when Definition of Done passes; mark blockers honestly.
3. Record decisions with context, alternatives, rationale, risks, tests and revisit conditions.
4. Record risks with evidence, player impact, mitigation, owner and trigger.
5. Keep research reports sourced and distinguish fact/inference/abstraction/fiction.
6. At checkpoints record changed files, tests, player route, evidence, defects, commit/push/Pages and next step.
7. Keep docs aligned with actual implementation.

Avoid fabricated evidence, vague “works” status or incomplete handoffs.
